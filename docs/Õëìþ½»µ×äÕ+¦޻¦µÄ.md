# 前端构建说明

本项目前端是「**多入口 HTML + 共享 CSS/JS**」结构。
改完前端代码后**必须重新构建**，否则线上还是旧代码。

---

## 一、目录结构

```
static/
  index.html            宣传落地页        ← 入口
  login.html            登录页            ← 入口
  register.html         注册页            ← 入口
  forgot.html           找回密码          ← 入口
  app.html              控制台            ← 入口
  admin.html            管理后台          ← 入口

  app.css               样式源码（可直接改）
  boot.js               启动引导（可直接改）
  app.js                ← 构建输入（源码，不要直接部署）

  dist/
    app.min.js          生产用：压缩 + 混淆
    app.raw.js          调试用：仅压缩

  vendor/               Vue / Element Plus / axios（第三方，勿改）
  *.gz                  预压缩文件（构建时生成）

docs/                   构建脚本与文档（不参与网站运行）
  build.js              压缩 + 混淆
  gzip_assets.py        生成 .gz
  package.json          构建依赖声明
```

> 6 个 HTML 入口**共用**同一个 `dist/app.min.js`。
> 每个入口只是 `<title>` 和 meta 不同，页面逻辑由 JS 里的路由决定。

---

## 二、改代码后怎么构建

### 1. 改样式或引导脚本

`static/app.css` 和 `static/boot.js` 是直接生效的，改完只需重新生成 `.gz`：

```bash
cd docs
python gzip_assets.py
```

### 2. 改业务逻辑（app.js）

```bash
# 1) 编辑 static/app.js
# 2) 构建
cd docs
node build.js

# 3) 重新生成压缩文件
python gzip_assets.py

# 4) 重启服务
sudo systemctl restart auto-douyin-sparks-pro
```

### 3. 改页面结构（HTML）

直接改对应的 `static/*.html`，然后重新生成 `.gz`：

```bash
cd docs && python gzip_assets.py
```

---

## 三、构建依赖

`build.js` 需要两个 npm 包：

```bash
cd docs
npm init -y
npm install terser javascript-obfuscator --no-audit --no-fund
```

**不想装 Node 工具链怎么办？**

可以退回「只压缩不混淆」：

1. 把 `static/app.js` 直接在 HTML 里引用（改 6 个入口的 script 标签）
2. 功能完全正常，只是源码可读、体积大一点

## 四、混淆强度取舍（实测数据）

| 配置 | 原始 | gzip 后 |
|---|---|---|
| 源码 app.js | 158.2 KB | 35.0 KB |
| 仅压缩 | 83.9 KB | **23.6 KB** |
| **轻度混淆（当前采用）** | 122.1 KB | **32.4 KB** |
| 重度混淆 | 476.1 KB | 163.5 KB ❌ |

**为什么不用重度混淆？**

字符串数组 + base64 + 控制流平坦化，会让 gzip 后的体积从 32 KB 涨到 **163 KB**，
首屏多下载 131 KB，只换来「更难读一点」。性价比太低，所以关闭。

当前混淆开启项：

- ✅ 所有局部标识符 → `_0x` 十六进制（3200+ 个）
- ✅ 禁用开发者工具调试（`debugProtection`）
- ✅ 自校验（`selfDefending`）：改一个字符整个文件失效
- ❌ 不做字符串数组编码（体积换不来安全）

用 `node build.js --with-strings` 可开启字符串数组，但体积会明显变大。

## 五、调试开关

生产构建保留了未混淆版本 `dist/app.raw.js`，但**默认返回 404**。

排障时临时打开：

```bash
# 允许访问 raw 版
EXPOSE_DEBUG_JS=1 sudo systemctl restart auto-douyin-sparks-pro
```

然后浏览器访问：

```
http://你的域名/?debug=1
```

**排障完记得关掉** `EXPOSE_DEBUG_JS`，否则未混淆代码可被任何人下载。

## 六、性能数据

| 场景 | 改造前 | 改造后 | 提升 |
|---|---|---|---|
| 首次访问 | 2057 KB | 503 KB | 省 76% |
| 二次访问 | 2057 KB | 91 KB | 省 96% |

原因：

1. **gzip 预压缩**：文本资源压到约 1/4
2. **长效缓存**：`vendor/` 带 `immutable` 头，二次访问 0 请求
3. **资源拆分**：CSS/JS 独立文件，改一处不用重下全部

---

## 七、别忘了

改完前端后，**`static/app.js` 本身不要部署到服务器**——
它就是源码，放在 `static/` 里任何人访问 `/static/app.js` 都能拿到。

发布时只需要 `dist/app.min.js`。
